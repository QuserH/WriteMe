# Agent Note: GitHub 保存可重建源码，本机环境与运行资料不入库

Status: implemented

## Problem

原生版与同步服务已在本机完成开发，远端仍停留在早期 Web 版本。本机目录同时包含下载依赖、自包含发布、QA 数据库和同步账号配置；直接上传整个目录会混入运行环境与私人资料。内置决策技能的演示图片也不参与项目构建或校验。

## Decision

Git 仓库保存当前原生版、同步服务、保留的 Web/Tauri 基线、测试、必要图标、工程文档和构建配置。依赖版本清单 `package-lock.json`、`Cargo.lock`、各项目的 `packages.lock.json` 及 Windows 发布锁文件是源码的一部分；依赖包、SDK、运行时、自包含应用和本机资料均由 `.gitignore` 排除。`.env.example` 保留空配置，真实 `.env`、密钥和 SQLite 及其 WAL/SHM 文件不提交。

`.dockerignore` 同时排除这些本机文件；镜像通过 Dockerfile 的锁定还原和多阶段构建获得依赖，不复制本机发布目录。`README.md` 提供新克隆的 `npm ci` 与 `dotnet restore --locked-mode` 入口。

Vite 的开发监听同时忽略 `native/`、`artifacts/`、`test-results/` 和 `playwright-report/`。这些不是前端热更新输入；在 Windows 上监听正在写入的原生渲染图会触发 `EBUSY` 并中断网页回归，忽略规则保留正常的 `src/` 热更新。

`.gitattributes` 将源码规范化为 LF，PowerShell 脚本在检出时使用 CRLF，并继续保留其 UTF-8 BOM。图标按二进制处理，避免 Windows 生成的锁文件和 Linux Docker 构建产生无意义的换行差异。

决策技能保留 `SKILL.md`、参考文档、脚本、模板和 `agent-notes-board.html`。上游说明改为本项目的入口，并链接原项目；演示 PNG/SVG 不再进入 Git，本机副本保留。应用图标继续跟随源码，包括原生项目引用的 `src-tauri/icons/icon.ico`。

本次重新上传以用户要求的当前源码快照建立新的根提交。旧 Git 历史与清理前源码先备份到被忽略的 `artifacts/repository-cleanup/`，远端沿用原仓库地址及私有可见性。该重建只用于本次明确授权的整理，日常开发继续使用普通增量提交。

## Verification

- 上传前核对全部索引路径、体积和敏感信息，确认忽略规则实际生效；锁文件、示例环境配置与必要图标必须存在。
- 从候选源码创建独立检验目录，还原依赖并验证构建，防止工作目录中的未提交文件掩盖缺失依赖。
- 干净副本暴露并修复开发与发布混用锁文件、导致 NU1004 的问题；独立发布锁覆盖 Desktop 与 Core，发布后再次执行普通锁定还原，配置约束留在 [原生架构](../architecture/2026-09-09-native-block-editor.md)。
- 运行 `npm run verify-notes`；推送后核对远端树与本地候选树一致，且 `main` 的可达历史只有新的根提交。

## Alternatives considered

- **复用旧仓库直接增量提交**：协作成本最低，也完整保留历史；但用户明确要求清理旧项目并重新上传，因此本次建立新根提交，旧历史只保留本地备份。
- **上传整个可运行目录**：下载后无需还原依赖，适合独立发布包；但 SDK、运行时和本机数据会与源码混杂，且可能暴露账号配置，因此发布目录和源码分开。
- **删除整个技能或 Web 基线**：仓库更小；但会丢失现用笔记校验流程、旧文档兼容参考及原生图标引用，故只排除无构建依赖的技能演示图片。

## Consequences

源码克隆包含重建所需的清单与实际资源，发布物、个人笔记和凭据不进入 Git。代价是首次开发需要自行安装 SDK 并还原依赖，离线开发必须另备包缓存；仅克隆源码不能直接双击程序。

历史重建会使其他旧克隆的分支关系失效，重新克隆最直接。旧历史及源码备份只在本机，不能把私有备份或密钥作为“缺失文件”强制加入仓库。后续新增二进制测试夹具或特殊资源时，应核对忽略规则并只为确需版本管理的路径加例外。
