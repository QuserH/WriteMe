# Agent Note: M6 自建同步——版本向量、多值寄存器与显式冲突恢复

Status: implemented

## Problem

WriteME 需要在完全离线时编辑，并在用户自建服务器上交换多设备资料。不能依赖第三方闭源云，也不能在并发编辑、删除或中途断网时按“最后保存时间”覆盖原文。现有原生文档树、统一撤销和 SQLite 本地库需要继续作为编辑路径。

## Decision

### 合并模型与持久化

- `SyncProtocol.cs` 实现基于状态的多值寄存器 CRDT，按 `document/<id>`、`space/<id>`、`folder/<id>` 分别保存版本向量和因果前沿。合并去重并删除已被支配的旧版本，保留真正并发版本；规范序列化保证重复交换可比较。合并满足交换、结合与幂等，不用时间戳选择胜者。
- 文档版本包含完整正文及收藏、位置、回收站、每日身份、页面外观和附件清单。正文并发与元信息并发都可能产生文档冲突；这是整篇版本保留，不是逐字符或逐块协同编辑。
- `SyncStore.cs` 将文档/容器变更、派生索引和待同步状态放在同一 SQLite 事务。每个资料库有独立设备 ID 与递增计数器；旧库导入副本获得新设备 ID、清空凭据并重新交换保留状态。不能直接复制已配置同步的活跃资料库作为第二台设备。
- 冲突未解决时禁止普通写入该对象，防止收藏、标题或外观保存隐式消除另一版本。UI 禁用当前冲突文档的编辑，其他文档继续可用；查看完整文字预览后可选择版本，或先把其他版本另存副本。选择产生支配已观察版本的新版本，旧对话框提交前再次校验前沿。
- 删除使用可合并的墓碑。并发删除和编辑都保留，未决状态优先显示可读正文；文件夹循环确定性地断开，缺失/删除的父容器有默认空间回退。并发同日笔记保留两份文档，按稳定 ID 决定每日快捷入口，不丢弃另一份正文。
- 正文真的被远端替换前保留本地版本。仅元信息变化不替换 `DocumentSession`，保留编辑历史和选区；无变化轮询不刷新页面草稿。派生标签、反链、全文索引在各端重建，最近打开时间、本机偏好、历史快照和凭据不上传。

### 网络、草稿与关闭时序

- `SyncClient.cs` 使用带游标的 HTTP 批次交换，默认 30 秒后台同步，也有手动入口。URL 必须 HTTPS，仅回环地址允许 HTTP；禁止自动重定向，认证错误要求重新登录，其他失败保留待上传状态。
- 网络传输期间可以继续编辑。响应进入 UI 提交时等待文档切换和预编辑结束，保存最新草稿，再短暂禁止编辑并串行合并；同时比较返回状态与当前状态，旧响应不能误清除网络期间产生的修改。
- 附件先检查服务端是否存在，再按哈希上传；接收文件先暂存，校验大小/哈希后替换为不可变资产。中断或缺失可重试，同步正文先到而附件未到时显示占位。并发版本及页面封面的引用也纳入传输。
- 关闭窗口先取消并等待同步、登录及退出操作，再保存并释放资料库；网络调用有取消和超时。退出登录保留本机笔记，清理本机凭据，并尝试撤销服务端会话。服务不可达时旧令牌等待过期。
- Avalonia 的 `TextBox.TextChanged` 会排队：远端标题加载后才回调，单靠 `_loading` 会把显示刷新误当新编辑，随后撞上冲突保护。标题处理器只有文字实际不同于当前存储标题才置脏；`NoteStore.Save` 对相同标题与正规化正文直接返回，不创建版本、更新时间或修订。该规则既避免关闭失败，也防止显示层覆盖冲突前沿。

### 服务端与账号

- `native/WriteMe.SyncServer/` 为 ASP.NET Core + SQLite 服务。`SyncServerHost.Build` 可被测试启动真实本机 HTTP 主机；`SyncRepository` 按账号隔离对象、游标读取和附件目录，不信任客户端给出的账号字段。
- 首次空库通过 `WRITEME_SETUP_USER` / `WRITEME_SETUP_PASSWORD` 创建账号；后续账号使用 `--add-user <name>`，密码从标准输入读取。密码为独立 32 字节盐加 PBKDF2-SHA256（210,000 次），比较用常量时间；随机会话只存 SHA-256 哈希，30 天过期，可退出撤销。
- 登录每来源地址每分钟限制 12 次；请求内容显式验证并限制大小。单批 24 MiB、最多上传 100 个对象；单对象全部并发 payload 总计 16 MiB、最多 32 个版本、每版本向量最多 256 个设备；资产最多 50 MiB。超过界限返回错误并保留本机待处理数据，不能静默丢弃冲突。
- `sync/Dockerfile` 使用 .NET 10 SDK 构建、ASP.NET 运行镜像和非 root 用户；`sync/compose.yaml` 映射持久卷 `/data`，只绑定宿主回环地址，端口由 `WRITEME_SYNC_PORT` 配置、默认为 8787。`compose.host-build.yaml` 在 Linux 默认构建网络不能访问依赖时仅给构建阶段使用宿主网络，运行服务仍保持隔离网络。外部访问通过 HTTPS 反向代理或 SSH 隧道。具体首次启动、账号、备份与升级见 [同步部署说明](../../../../sync/README.md)。
- Windows 的 `SyncCredentials.cs` 使用当前用户 DPAPI，附加资料库路径作为熵，保存令牌而不保存密码；非 Windows 不降级为明文持久化。服务器可读取同步内容和文件，不提供端到端加密；账号隔离不等同于不信任服务器。

## Verification

- `SyncTests.cs` 覆盖三设备并发和收敛、编辑与删除冲突、乱序/重复合并、元信息、文件夹循环、每日碰撞、网络期间继续编辑、分页和服务端重启、失败/取消后的重试、账号隔离、会话撤销、资产与封面校验传输、旧库新设备 ID 和 DPAPI。
- 测试启动真实 HTTP 主机和多个隔离 SQLite 客户端，并调用登录、同步、资源接口；不是只验证内存中的合并函数。
- `WorkspaceInteractionTests.cs` 通过真实 HTTP 服务驱动原生设置登录、元信息同步、并发正文、冲突预览与版本选择；`KnowledgeLibraryTests.cs` 单独验证相同内容保存不改变冲突前沿。`sync-settings.png` 与 `sync-conflict.png` 已渲染检查。
- `npm run native:build` 无警告/错误，原生全套 153 项通过。Windows 自包含发布版的空资料库 `--smoke-test` 也通过。
- 在用户授权的 Linux ARM64 主机上，Docker 29.7.1 / Compose 5.3.1 完成真实多阶段镜像构建、锁文件 restore、非 root `app` 启动和命名卷挂载。原机器的 Docker 代理访问 MCR 失败，采用官方直连下载并核对 SHA-256 后导入镜像；构建桥接网络访问 NuGet 失败，使用构建阶段的宿主网络覆盖解决，依赖安全检查未关闭。
- Windows 的两个独立 `NoteStore` 通过 SSH 转发访问该容器，验证文档/空间/文件夹/关联/收藏/外观、两个附件（含封面）、离线双版本、显式选择收敛、跨账号资源隔离及退出撤销。随后 `--force-recreate --no-build` 重新创建容器，第三份空资料库恢复两篇文档、两个资产和已解决前沿。结果在本机 `artifacts/native/qa-remote-sync/initial-result.json` 与 `restart-result.json`，测试账号与用户空账号隔离。
- 这项跨主机 HTTP/SSH 验证覆盖 Linux ARM64 服务端和 Windows C# 客户端核心；公网 HTTPS 代理、证书部署、长时间运行与 Android/macOS/Linux 编辑器输入仍未验收。

## Alternatives considered

- **不做同步，维持纯本地并用 ZIP 交换**：部署负担最低，容易审计和恢复；无法满足用户的多设备目标。ZIP 保留为独立迁移手段。
- **服务器权威库加最后修改时间覆盖**：协议简单、存储小，适合单设备串行使用；离线设备的时间不可当因果关系，覆盖会丢掉未见修改。选择版本向量保留并发事实。
- **Yjs / Automerge 逐字符协作**：能够自动合并同段输入，实时多人协作更顺畅；当前原生文档/历史不属于这两种运行时，桥接、稳定字符身份和 IME 事务需要额外迁移。当前使用整篇多值寄存器交付离线交换，出现频繁同篇并发时再评估更细粒度模型。
- **第三方商业云**：账号、运维和可用性生态成熟；不满足既定自建方向。服务器仍需要用户维护 TLS、磁盘与备份。
- **WebSocket 长连接**：低延迟通知适合实时协作；当前是离线资料库交换，游标 HTTP 更容易重试和部署。未来可增加通知，不能改变合并语义。
- **明文令牌配置文件**：跨平台最简单、可直接复制；本机登录状态不应随普通备份传播。Windows 使用 DPAPI，其他平台当前只保留进程会话。

## Consequences

- 收益：断网继续编辑、重试幂等、并发内容保留，账号及附件经过真实接口验证；同步不引入 WebView，也不依赖第三方云。
- 代价：整篇版本增加网络和磁盘成本，同篇并发需要用户处理；即使只改不同字段也可能冲突。服务器留存因果前沿与墓碑，暂不自动垃圾回收；协议与文档 JSON 必须共同演进。
- 运行边界：单进程 SQLite 服务，尚无跨实例高可用、账号恢复/密码重置界面、端到端加密和逐字符协作。Docker 已在 Linux ARM64 实测；公网 TLS 与长期运维仍需对应环境验证。更换服务器/账号会将当前整个资料库与新目标合并，空库开始的独立账号应使用独立 `--data-dir`。
