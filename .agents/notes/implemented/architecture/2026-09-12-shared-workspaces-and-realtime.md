# Agent Note: 共享工作区、管理员账号与原生和网页实时协同

Status: implemented

## Problem

用户需要把 WriteME 部署到局域网 Docker 服务，由管理员开通账号，用户设置自己的 ID 并加入共用工作区，在网页和 Windows 原生端同时编辑和评论。现有 M6 是同账号的整篇离线版本交换，不能自动合并同段输入或同时回复，也没有成员权限和管理员界面。桌面系统标题栏与应用顶栏分离，窗口边缘缺少一体性。

实际手机使用还暴露了桌面侧栏占用窄屏、回复和发送区被挤出视口的问题。用户要求段下评论入口、可设计头像、六位起的新密码，并让独立后台支持修改管理员自身账号及查看各账号的数据与登录设备。

## Decision

### 独立入口、账号和权限

- 沿用 ASP.NET Core 与 SQLite。`/admin` 是独立管理网页，包含自己的登录、权限提示、账号列表、创建、停用和临时密码重置；笔记网页 `/team` 和原生窗口不嵌入管理面板，也不放后台导航。代码分别位于 `src/admin/` 与 `src/shared/`，入口按路径懒加载。
- 空库的启动账号和迁移旧库的首个账号拥有管理员权限。管理员开通登录账号；用户首次登录设置唯一公开 ID、显示名和自己的密码。更改临时密码后撤销其他会话，保留当前正在完成设置的会话；停用和重置密码撤销旧会话。
- 工作区成员使用 `owner/editor/viewer`，按用户 ID 添加。所有者管理成员，编辑者修改正文并评论，读者可选择复制、展开折叠和阅读回复。最后一名所有者不能被移除。评论作者取当前账号；只可编辑自己的消息，所有者可删除违规消息，保留回复关系。
- 浏览器使用同源 HttpOnly、SameSite=Strict Cookie；写请求与 WebSocket 验证 Origin。原生使用单独的 DPAPI 凭据。个人离线资料库与 [M6 整篇同步](2026-09-08-sync-docker-crdt.md) 保留，共享资料通过独立入口、草稿库和权限处理，不自动上传个人笔记。

### 稳定块与双端协作

- 账号改名不改写既有评论作者快照。`account_display_names` 与资料变更同事务记录该账号曾用名，服务端接受同一 `authorId` 的旧名字，支持改名前离线产生的合法评论；仍拒绝其他账号身份、从未使用的名字及既有消息作者篡改。显示端根据当前成员资料展示最新名字和头像。

- 共享正文使用 Yjs `13.6.32` 与 Yrs/YDotNet `0.6.0` 的 v1 更新、UTF-16 文字坐标。原生继续使用 C# `DocumentSession` 与 AvaloniaEdit，不增加 WebView。服务器先在临时副本验证，再同一 SQLite 事务持久化正文和评论凭据，成功后才广播与 ACK。
- 稳定块 ID 对应独立 Y.Map，文字为 Y.Text，子项顺序为 ID 数组，父级为块属性；移动保留文字身份。投影确定性处理重复引用和循环，空容器的占位段落由固定算法生成 ID，两端一致。格式按独立属性更新，段落锚点与逐条消息独立存储，回复指向同一讨论内的消息。
- 评论消息键必须等于消息 ID。服务器校验新增作者、已有作者/时间/回复对象不可篡改；允许撤销合法讨论删除时逐字恢复其他成员的消息，但凭据绑定文档、讨论、消息 ID 与完整内容，不能把原消息移植到新讨论。隐藏/墓碑块也验证属性、格式与类型，拒绝的数据不进入持久状态。
- WebSocket 连接验证会话和工作区角色；成员、文档状态或账号改变后通知或断开连接，广播前再次检查接收方权限。最后一个连接释放空房间，发送有超时。共享上限为 16 MiB CRDT 状态、50,000 块、80 层、4,000,000 UTF-16 字符；评论沿用 1,000 条讨论、10,000 条消息及单消息 20,000 字上限。
- 本地编辑通过 CRDT 历史撤销，只撤销自己的操作。`DocumentSession` 的个人 200 项历史不改，共享会话接入独立 CRDT history adapter。范围格式、表格和分栏区域仍通过根会话提交；文字、标题和评论预编辑期间延后合并远端内容，相对位置恢复选区。

### 个人资料与后台数据管理

- `AccountProfiles` 为创建账号、首次设置、管理员重置和本人修改统一规定 6–1024 个字符的密码。`PATCH /api/profile` 修改个人 ID、显示名和头像；本人修改密码另用当前密码校验，保留当前会话、撤销其他设备。管理员编辑自身登录名或密码不进入首次设置；替他人重置仍使用临时密码流程。稳定账号 ID 保持文档和工作区归属。
- 网页和原生“个人设置”支持文字/表情、八种配色、图片拖动裁剪和缩放。上传端将 JPG/PNG/WebP 转成小尺寸 PNG；服务端限定 PNG 签名、IHDR、正方形尺寸不超过 256px、大小不超过 128 KiB。只保存当前头像及 SHA-256 版本，认证读取仅限本人、管理员和共同工作区成员。头像不放进文档 CRDT；原生图片缓存随窗口释放。
- `/admin` 的账号与同步页面提供搜索、状态筛选和真实统计。详情展示该账号的个人文档/并发版本、附件字节、可访问的共享工作区/文档/回收站、最近成功交换时间和登录设备；工作区不会被重复计入全局独立文档数。个人文档和登录列表最多展示最近 200 项，编辑连接与有效登录分别统计，不能用最近交换时间宣称所有设备已同步。
- 暂停写入保留读取权限、现有文档和设备草稿，M6、共享更新及附件落盘均检查；共享 WebSocket 保持连接，通知权限变化，恢复后发送保留的差异。权限请求按序号丢弃迟到响应，暂停时迟到 ACK 不显示保存完成。暂停与共享事务/附件最终落盘之间的竞态再次校验。
- 管理员可退出指定设备或整个账号的设备；处理自己时批量退出保留当前会话。撤销连接先从广播列表移除，再发送错误与关闭帧，避免随后的在线成员广播立即 abort 并丢掉退出说明。统计和设备接口不返回令牌或令牌哈希。

### 固定版本原生适配

- YDotNet 0.6.0 的默认 ID 生成器误用 XOR，碰撞范围过小。显式使用加密随机 `uint32` client ID，与 Yjs 默认宽度一致；较大 53 位随机 ID 在固定版本原型中未稳定收敛，不能换回未验证的实现。
- Yrs 的 StickyIndex 创建会分裂内部项，必须使用可写事务；在只读事务中创建会触发原生 panic。文末用相对末尾哨兵，中间光标使用编码 StickyIndex。固定版本的 managed Dispose 未释放索引，显式调用 `ysticky_index_destroy`；升级 YDotNet 时须重新核对 ABI、销毁和中文/emoji 中部光标回归。

### 草稿、只读阅读和界面

- 本机 `shared-drafts.db` 与浏览器 IndexedDB 按服务器、账号、文档隔离。断线期间可继续当前文档编辑，重连交换状态向量；只有对应本地修订收到 ACK 才显示“所有更改已保存”。失败保留草稿并停止写入，提供导出及重新打开服务器版本；网页切换到新缓存代次，旧缓存保留，原生须成功另存草稿后才替换。
- 读者的展开状态只在本机投影/DOM 中改变，不写正文、不进入历史或广播；正文、格式、历史、评论写入受统一只读保护。原生表格/分栏范围继承根权限，仍保留选择、复制、查看原段和回复引用导航。
- 原生标题栏与顶栏合并，保留拖动、最大化/还原、窗口控制和关闭保存。根据实际 Craft 页面采用冷白 `#FCFDFE`、白纸、深色文字 `#1A1C1E`、轻边界和圆角，蓝色用于主操作、选择和链接；用户明确不要绿色，也不接受大块灰色登录插画。登录为居中表单，正文为纸张区域。原生主按钮包含悬停、按下和禁用状态，个人设置标签明确标记当前页。
- 共享网页复用分类斜杠菜单、块拖动和选区工具栏，包含表格与分栏。评论摘要在段落下方显示小头像、数量和时间；ProseMirror widget 参与排版但不进入正文、复制或历史，折叠标题和表格段落也保留入口。桌面打开贴近段落的浮层，外部单击关闭并继续原本编辑操作；原生使用同一段下摘要与就近浮层，全文入口保留侧栏。原生行盒规则见 [段落评论](../feature/2026-09-11-native-comments.md)。
- 手机采用可收起的导航抽屉和精简顶栏，隐藏区域 inert；表格在自身范围横向滚动，分栏纵排。评论以底部圆角弹层显示，列表独立滚动、输入区固定可见，不在打开阅读时主动弹键盘。`visualViewport` resize/scroll、safe-area 和 `interactive-widget=resizes-content` 共同约束实际可见高度；回复、删除确认、设置和后台详情都能在窄屏内操作。
- 未发送评论按当前文档、段落及回复/编辑目标保留，关闭后重开可继续；草稿只保存在当前页面进程，不宣称刷新后仍存在。中文预编辑期间不提交。删除中间回复保留墓碑和后续消息，计数只包含未删除消息。个人 ID 的 HTML pattern 显式转义短横线，兼容新版 Chromium 的 Unicode v 校验。

### 部署

- Docker 使用 Node 构建静态前端，再复制到 ASP.NET 运行镜像的 `wwwroot`，最终容器不需要 Node。Vite 的部署构建指定根路径，使 `/admin/` 等路径能正确加载静态资源；旧 Tauri 构建仍保留默认相对路径。
- Compose 默认 `127.0.0.1`；`WRITEME_SYNC_BIND` 可显式开放局域网，端口由 `WRITEME_SYNC_PORT` 设置。共享原生入口允许 HTTPS，以及回环/RFC1918/IPv6 ULA 地址的 HTTP；个人 M6 的 HTTPS 规则不放宽。公网反代需同时转发 WebSocket 和正确的同源请求信息。
- Linux ARM64 的 `writeme-sync` 项目在备份停机一致快照后升级，保留原持久卷及 18789 端口，按用户要求开放 LAN。手机与账号版本的运行目录为 `/home/quser/writeme-mobile-accounts-9093b78`，旧目录与回滚镜像保留；镜像 `writeme-sync:mobile-9093b78` 使用服务器已有的 ECR Node 镜像通过 `NODE_IMAGE` 构建参数构建，其他依赖继续按锁文件还原。
- 独立 QA 容器通过全部 3 组共享网页回归；重启前后账号、共享状态及评论凭据哈希一致，重启后改名账号、头像 PNG 内容哈希和 4 个账号的数据详情继续可读。正式服务验证 `/team`、`/admin`、`/admin/` 的手机入口及静态资源；生产账号身份/密码字段、个人同步记录、工作区、共享文档和评论凭据在升级前后哈希一致。现行用户密码不参与自动测试，登录和资料修改使用隔离账号验证。
- 整个资料目录在停止本项目容器后备份，并在服务器与本机各保存一份、核对压缩包 SHA-256。状态校验通过 SQLite 读事务执行，离线 WAL 副本允许在备份目录创建共享内存侧车文件；不复制正在写入的正式数据库。其他服务不重启，凭据、备份、环境、发布物与测试截图不入 Git。

## Verification

- `AccountManagementTests` 通过真实 HTTP/WebSocket 验证六位密码、管理员改名且保持当前会话、密码撤销其他设备、头像访问及重启、历史作者快照、真实 M6/附件统计、暂停保留草稿与恢复写入、指定设备退出。`SharedWindowTests` 通过原生个人设置修改名字、头像文字/颜色和密码，核对当前编辑会话及后续评论身份。
- `tests/shared/mobile-and-accounts.spec.ts` 使用 Chromium 的安卓触摸场景验证 360/390/412 宽度、导航、段落/单元格/折叠标题评论、三级回复、草稿重开、删除占位、IME 和压缩视口，以及个人资料、密码与独立后台改名/头像/设备管理。截图验证包含窄屏、400px 可见高度和手机后台；这是浏览器设备模拟，不替代真实安卓系统键盘验收。

- `SharedReplicaTests` 覆盖中文/emoji、独立格式、仅本地撤销、移动同时输入、并发回复、稳定占位、文中与文末相对光标、只读展开及局域网 URL。回复断言按消息身份核对父对象与作者；同毫秒消息用 ID 打破排序平局，不能假定最后创建的消息总在合并列表末尾。
- `SharedServerTests` 和 `SharedValidationTests` 通过真实 HTTP/WebSocket 验证角色、作者冒用、临时会话撤销、无效载荷、跨讨论冒用、ACK 持久化、撤权和重启。
- `SharedWindowTests` 验证两原生窗口、实际输入、回复、权限切换、只读选择与回复导航，个人库不自动上传；另启动真正 Chromium，与原生编辑表面进行同位置输入、格式、撤销、回复的回复和离线重连。浏览器导航后等待编辑器收到真实 `selectionchange` 再切换输入格式，避免脚本在 DOM 光标已移动、模型光标未更新时按快捷键；输入后与合并后分别检查斜体。
- `tests/shared/workspaces.spec.ts` 验证独立后台、两个浏览器账号、工作区成员、正文、段落回复、分类菜单、表格、离线恢复及读者本机展开。该测试也在 Linux ARM64 Docker 镜像中运行，重启后 CRDT 状态哈希与评论保持一致。
- 浅色、深色、窄窗口和管理页渲染图使用隔离资料库与测试账号生成；无用户桌面窗口控制。299 项原生回归、45 项 Web 基线回归和 3 组共享网页端到端回归通过。普通及 win-x64 发布锁文件均保留，发布后普通锁定还原通过；新目录内的无窗口 smoke 验证随包运行时、SQLite 与 Yrs 中文/emoji 编辑回环。

## Alternatives considered

- **复用 M6 并缩短轮询**：存储改动最小，已有离线保护；仍把同时输入和回复当成整篇冲突，不能满足实时协同。
- **版本号加三方文本合并**：服务端权威、协议易审计，少一个原生依赖；需要自研富文本偏移、结构移动和选择性撤销，复杂度集中在容易丢内容的路径。采用跨运行时验证的 CRDT 序列，保留应用层权限检查。
- **浏览器 Y.XmlFragment 绑定**：TipTap 生态成熟；原生 XML 属性接口与对象移动仍需额外适配，结构重建也会改变文字对象身份。采用稳定块对象和双端适配，代价是维护双方序列化与回归。
- **桌面嵌入同一网页**：只维护一套编辑 UI；违反用户持续的无 WebView 约束，因此保留原生编辑。
- **管理员面板嵌在笔记侧栏**：入口方便且少一页；用户明确要求单独的 `/admin`，因此页面、入口和布局分开。
- **手机直接缩窄桌面评论侧栏**：组件最少，位置一致；正文与回复争抢不足 400px 的宽度，键盘又压缩高度。选用同一讨论模型、桌面段落浮层和手机底部弹层，代价是维护两种定位规则。
- **在正文中嵌头像或接受远程头像 URL**：文档备份可自行携带图片、接入最简单；头像修改会放大协作状态，远程 URL 还会引入失效和外部访问。头像归账号并经过认证读取，代价是共享成员资料需刷新。

## Consequences

- 收益：网页与原生端能以各自账号在共同文档输入和回帖，个人离线使用保持独立，后台不干扰写作界面。
- 代价：两套编辑适配与固定原生 ABI 增加维护面；CRDT 收敛不能替代应用权限和格式验证。共享 CRDT 历史当前不执行自动压缩或 200 项裁剪，受文档总大小上限约束；不把小规模验证写成长时间/大团队性能保证。
- 当前边界：共享附件上传、封面与个人资料库迁入、完整网页原生功能对等、@提醒/通知、匿名分享、共享网页的离线冷启动、多进程部署、端到端加密未实现。共享未支持的块保留原始数据，不能宣称所有 Craft 功能完成；公网 HTTPS 代理需独立部署验证。
