# Agent Note: M3 笔记关联——标签、稳定双链、反向链接与收藏

Status: implemented

## Problem

原生编辑具备文字格式，但文档彼此孤立。用户要求完成 M3 及后续里程碑后统一排查。标签需要可筛选，笔记链接需要在目标改名后仍有效，反向链接必须能找到折叠内的来源，收藏需要跨重启保留。

## Decision

- `NoteReferences.cs` 从完整文档树识别正文 `#标签`。Unicode 字母、数字、组合音标、下划线、短横线和斜线构成标签，按 NFC 与不区分大小写的键去重；代码、网址及链接文字不参与。标题的 `# 空格` 快捷输入保留原规则。
- 输入 `[[` 或使用 Ctrl+Shift+K 搜索笔记，可选择现有文档或明确新建并链接。显示文字保存在 text run，`noteLink.attrs.documentId` 保存稳定目标 ID；改名不改写用户的链接别名，目标删除保留可识别的失效链接。Ctrl+单击或 Alt+Enter 打开链接，普通单击继续编辑。
- `ReferenceCompletion.cs` 用原生控件完成标签和链接补全，提交核对会话、修订与选区，中文预编辑确认不插入链接。正文链接插入/移除走 `DocumentSession` 统一历史。新建目标文档是独立操作，撤销链接不会隐式删除目标。
- `KnowledgeStore.cs` 维护收藏、标签、链接及索引版本表，原 `documents` 契约保持不变。正文与派生索引在同一事务更新，首次升级补建索引；收藏作为元信息持久化，不改变正文历史与更新时间。
- 来源定位保存内容路径与局部偏移，每次保存重建，不能持久化运行期节点 GUID。遍历支持的容器及收起子树，未知原子块与代码不参与标签/关联抽取。导航前保存当前草稿并按最新内容定位。
- 空间模式提供收藏和标签筛选，当前文档模式在标题目录下显示“反向链接”和“链接到”及上下文。回收站内来源不出现在有效反链中，回收站内目标显示不可用。空间、文件夹、搜索和卡片总览复用 [资料库导航](2026-09-10-library-and-search.md)。
- 文档收藏及正文随 [M6 同步](../architecture/2026-09-08-sync-docker-crdt.md) 交换；标签和反链由各端重建，不把派生索引当同步事实。

## Verification

- `KnowledgeLibraryTests.cs` 覆盖 Unicode 边界、代码/网址排除、跨样式链接、单次撤销、改名/删除/重开、旧库补建、收藏时间独立，以及故意让索引写入失败后的整笔事务回滚。
- `WorkspaceInteractionTests.cs` 通过原生指针/键盘验证链接补全、中文预编辑、旧文档草稿失效、标签筛选、收藏和隐藏反链定位。渲染图位于 `artifacts/native/qa-m3-m6/`，包含 `reference-completion.png` 和 `document-backlinks.png`。
- `npm run native:test` 全套 153 项通过。测试使用隔离 SQLite，不操作用户窗口与资料库。

## Alternatives considered

- **只用标题文本存双链，打开时匹配**：数据直观且无需新标记；但改名和同名文档会错连。选择文档时绑定 ID，显示文字仍作为可编辑别名。
- **每次导航解析所有正文**：没有索引一致性维护，初期代码最少；资料库增长后重复 JSON 解析进入持续导航路径。采用事务内维护、可重建的派生表。
- **复用网址链接或 UI 收藏缓存**：现成入口可以快速复用；内部文档还有改名、删除、反链及跨重启语义，因此使用独立 noteLink 和持久元信息。
- **不增加导航，只保留输入语法**：界面变化小；但用户无法浏览标签、收藏与来源。复用现有左侧两种模式承载可操作的列表。

## Consequences

- 收益：笔记改名不破坏关联，折叠内来源可直接定位，收藏和标签可用于资料库筛选，格式与链接共用文档历史。
- 代价：保存需要重建当前文档的索引，路径定位依赖最新快照；新节点类型必须同步抽取器、渲染和回归。别名不会随目标标题自动改名，这是保留作者文字的明确选择。
- 边界：标签是正文语法，不提供独立于正文的标签管理器；单篇 Markdown/JSON 不重映射外部资料库的目标 ID，完整资料迁移使用带 ID 映射的 ZIP 备份。
