# Agent Note: M5 页面外观、附件与资料可携带性

Status: implemented

## Problem

用户要求完成后续原生能力。页面字体、主题、附件和信息缺少真实入口；只有正文 JSON 导出，无法携带资料库中的文件。每日笔记、演示与恢复也需要直接使用现有文档。

## Decision

### 页面、主题与信息

- `WorkspaceStore.cs` 的 `PageAppearance` 按文档保存字体类别、字号、宽度、背景、文本色、行距、封面资产及分割线样式。默认 sans / 15px / 860px / 1.2 行距，颜色跟随主题、无封面、细线；UI 提供四类字体、12–24px 字号、1–2 行距、860/1200px 页宽、预设/十六进制色、封面选取/移除及细线/点线/隐藏。
- `MainWindow.Appearance.cs` 和 `PageDivider.cs` 接通右侧页面、信息入口。页面默认文字色与已有选区 marks 分开，整页设置不污染正文历史；页面元信息随同步保存。复制文档同时复制外观。
- `Ui.cs`、`Ui.MarkupColors.cs` 和动态 XAML 资源负责浅色、深色与跟随系统主题。正文标记、层级线、代码/标签/链接颜色依据实际页面底色决定，深色应用中的浅色自定义页面仍可读；设置窗口背景也随主题变化。
- `AppPreferences` 只保存本机主题与 [幽灵块不透明度](2026-09-09-settings-ghost-opacity.md)，不进入同步和 ZIP。页面表单核对当前文档并保护中文预编辑；无内容变化的同步轮询不重建表单草稿。
- 信息面板显示创建/修改时间、位置、非空白 Unicode 字符数、区块/附件数与估算阅读时间，并提供移动、复制、收藏、备份恢复、回收站、演示和同步入口。估算阅读时间按 300 字符/分钟计算，不作为真实阅读测量。

### 附件与交换

- 用户选择的文件复制到 `<data-dir>/assets/<SHA-256>`，资产 ID 为大写 64 位十六进制哈希，单文件上限 50 MiB；先暂存、计数及校验，再进入不可变资源库。同内容复用文件，正文只记录 ID、名称、类型与大小。插入/删除通过 `DocumentSession`，撤销不删除物理文件，以免破坏历史引用。
- `AssetElementGenerator.cs` 原生预览本机图片与附件块，不自动下载网络资源。封面引用相同资产库，备份及同步都包含封面；远端附件未到达时保留占位并允许同步重试。点击文件会将副本交给系统应用打开，不改动资料库内按哈希保存的原件。
- `NoteMarkdown.cs` 使用锁定的 Markdig 1.3.2 处理常见标题、正文、列表/待办、引用、代码、链接和图片。自定义折叠/未知块使用明确的 `writeme-json` 围栏保留结构；标准 Markdown 不能保存全部文字 marks、页面元信息和跨资料库的链接身份。
- Markdown 导出将正文资产复制到相邻 `assets/`。导入识别独占一段的 `assets/<hash>` 附件链接；`ImportLocalAssets` 递归复制普通图片和自定义围栏内的资产。带 hash 的文件必须校验内容，只读取所选文档目录内无重解析点的相对路径，不跟随越界、绝对路径或网络 URL。单篇文本先受 8×1024×1024 个 UTF-16 单位的长度限制，持久化另受同步载荷上限约束；JSON 导入/导出保存精确正文结构，完整资料使用 ZIP。
- `LibraryBackup.cs` 的版本 1 ZIP 保存文档、空间/文件夹、收藏、回收站、每日身份、页面外观与已引用附件。导入先检查清单、重复/非法 ID、循环、归属、资源长度及哈希，再在事务中创建副本并重映射内部链接；不覆盖已有笔记。旧纯文本只在导出快照中正规化，不回写原库。
- ZIP 不包含登录令牌、同步前沿、本机主题、最近打开时间或历史备份。上限为 10,000 文档、1,000 空间、10,000 文件夹/附件、20,000 ZIP 条目、128 MiB 清单及 1 GiB 总附件。损坏资源不能生成半份文档；已验证但随后导入失败的未引用资源可留在哈希库中。

### 日常使用与恢复

- `DailyNote` 按空间和本地日期唯一，支持当天入口与设置中指定日期。当天笔记在回收站时恢复原身份；跨设备并发创建同日笔记由同步层保留两份内容，确定一份作为快捷入口。
- 本地版本最多 50 份，普通编辑最多每五分钟捕获一次修改前快照；远端正文替换和显式恢复前另保留快照。恢复进入统一正文历史，原始内容仍有备份；本地快照不作为云端版本历史。
- `PresentationWindow.cs` 用原生只读窗口按顶层一级标题/分割线分页，呈现常见文字格式与本机图片。左右/PageUp/PageDown/空格翻页，Home/End 首末页，Esc 退出；演示不改写正文。

## Verification

- `KnowledgeLibraryTests.cs` 覆盖 Markdown 常见结构、自定义块与相邻附件往返、嵌套资产哈希拒绝、路径边界、ZIP 副本/链接映射、损坏及空清单拒绝、外观与偏好重开、每日身份和本地恢复。
- `WorkspaceInteractionTests.cs` 通过原生指针/键盘验证页面/信息、深色设置、图片、封面备份、幽灵块、只读演示与卡片导航。渲染图位于 `artifacts/native/qa-m3-m6/`，已检查深浅色页面、`page-cover.png`、`native-image.png` 与 `native-presentation.png`。
- `npm run native:test` 全套 153 项通过；全部自动 UI 验证使用隔离资料库，不操作用户桌面窗口。

## Alternatives considered

- **不做页面元信息，复用正文 marks**：存储入口少；但整页字体和背景会污染每段格式及撤销历史。页面与富文本各自保存，渲染时组合。
- **直接引用用户原文件路径**：零复制、省空间；移动源文件或换设备会使笔记失效。内容寻址副本支持去重、备份与校验传输。
- **只保留 JSON 导出**：精确保存未知节点，交换契约最稳定；但无法携带文件和空间结构。JSON 用于正文保真，Markdown 用于常见交换，ZIP 用于完整资料副本。
- **让 ZIP 直接覆盖本机库或复制活跃 SQLite**：恢复快、可保持 ID；却可能覆盖新笔记并漏掉 WAL 事务。导入新身份副本并重映射链接，服务器的物理备份另走停止服务或 SQLite 在线备份流程。
- **用 WebView 演示与预览**：可复用网页排版和 HTML 生态；违背当前原生核心约束，并增加页面执行环境。使用只读 Avalonia 控件，接受当前演示格式范围。

## Consequences

- 收益：页面外观和信息有真实入口，文件不依赖原路径，每日记录、恢复及携带整套资料有完整的本机路径。
- 代价：需要维护资产库、导入验证、主题资源与页面对比度；哈希资源暂不自动垃圾回收。Markdown 只保证已声明的常见格式，ZIP 是包含封面和空间结构的迁移方式。
- 边界：正文中的嵌套页面/卡片、任意高亮取色、完整富文本剪贴板和屏幕阅读器接口尚未实现。原生演示是只读分页视图，没有 PowerPoint 导出；Windows 验证不代表其他平台验收。
